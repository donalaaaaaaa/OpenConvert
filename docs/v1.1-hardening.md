# OpenConvert 1.1 硬化清单

依据 2026-08-22 发布后的优先级表。v1.0.0 已挂 GitHub Releases；本轮不再堆格式，先把签名、CI、恢复和大文件做实。

## 建议顺序（一轮开发）

1. 新 keystore（本文件 + `docs/signing-rotation.md`）
2. 真机 / CI instrumentation
3. 系统杀进程恢复测试
4. 100 MB–4 GB 大文件矩阵
5. 拆 `MainViewModel`
6. 拆 `OpenConvertApp`
7. MediaCodec 失败黑名单 / 降级
8. Tag → 签名 → GitHub Release 自动化

## P0

| 项 | 状态 | 说明 |
|---|---|---|
| 更换正式发布 keystore | 已生成 v2 + 写入 GitHub Secrets | 旧证口令已进 git 历史。v1.0.0 仍用旧证以便覆盖已装用户；**下一版**改新证，versionCode 必须升高。见 `docs/signing-rotation.md` |
| CI 加 instrumentation | 部分 | GitHub-hosted 模拟器是 x86_64，本仓库 native 只有 arm64，不能在 ubuntu runner 上跑真转换。JVM 单测继续每 PR 跑；真机用 `scripts/run-device-tests.ps1`；workflow_dispatch 预留 self-hosted |
| Release 构建链自动化 | 已接 tag 工作流 | tag `v*` → 单测 → Secrets 签名 Basic/Office APK+AAB → SHA256 → GitHub Release |
| 清理 Office 动态 Pack | 已删 | `OfficePackManager` / `PackLibraryLoader` 已移除；PHY110 上假 pack 隔离测试通过 |
| 系统杀进程恢复测试 | 已补 | `recoverOrphans()` 抽出。PHY110：RUNNING/PENDING 无 work → FAILED。真 `am force-stop`：`scripts/verify-force-stop-recovery.sh`；WorkManager 仍持有任务时保持 PENDING/RUNNING，丢掉才标 FAILED |
| 大文件到 4 GB | 部分 | PHY110：`streams4Gb`、JPEG→PNG、100MB ZIP、**4GB GZIP 实转**均通过。4GB 视频按产品决定不测，等社区反馈 |
