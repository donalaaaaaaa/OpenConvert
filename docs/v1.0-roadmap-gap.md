## 阶段外发现的既有缺陷

1. **`canConvertLocallyTo` 与 `ConversionGraph` 双轨**（`FileFormat.kt:75`）。IMAGE / AUDIO 分支用 `category == 同类 && this != target` 的旧规则，VIDEO / ARCHIVE / OFFICE 分支才查 Graph。后果：UI（`MainViewModel:53` 的 `engineAvailable`）会放出 JPG→AVIF / JPG→HEIC / JPG→GIF / JPG→BMP / JPG→TIFF，而 Graph 与 `ImageConverter` 都不支持这些目标 → 转换到 registry 才失败。

2. **Graph 声明了无引擎的边**。`PNG → PDF` 在 Graph 里存在，但 `ImageConverter.supports` 要求输出为 IMAGE，`ConverterRegistry` 因此没有该边的引擎；图片→PDF 实际走独立的 `IMAGES_TO_PDF` kind。Graph 作为"能力单一来源"与 registry 实际能力不一致。

3. **`ConversionException` 未接入**。11 类结构化错误（含 `InsufficientStorage(required, available)`）定义完整但生产路径全部返回裸字符串，计划书 §7.3 要求的"需要 2.1 GB / 剩余 1.3 GB"这类信息无处可取。

4. **仓库体积**：`.git` 1.7 GB。**已核实：LFS 早已配置**（`.gitattributes` 有
   `*.so filter=lfs`），`liblo-native-code.so` 在 git 里是 134 字节指针，v1.0.0
   已成功推上 origin。不需要重写历史。实际约束是 GitHub LFS 免费额度
   （1 GB 存储，当前 893 MB）。

5. ~~**Release 签名口令硬编码**在 `app/build.gradle.kts:26`。~~ → ✅ 已外置到
   gitignore 的 `signing.properties` + 环境变量，缺失时产出 unsigned APK。
   注意该 keystore 口令已进历史，视为泄露，正式发布需换新 keystore。

6. 未使用变量：`ConversionAdvisor.kt:97`、`ConversionEngineSelector.kt:75` 的 `hwProfile` 取值后未使用。
